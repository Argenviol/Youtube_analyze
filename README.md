# 버추얼 크리에이터 팬덤 애널리틱스

> **📊 멤버별 유튜브·노래 조회수 정리 (2026-10-25 기준)**
>
> 영상·쇼츠·노래 평균과 최고 조회수, 멤버별 특징 →
> [`멤버별_조회수_2026-10-25.md`](멤버별_조회수_2026-10-25.md)

버추얼 크리에이터 그룹 **스텔라이브**를 소재로, 공개 데이터만으로 팬덤 지표와 실제 재무 성과를
연결해 본 데이터 분석 포트폴리오입니다. 게임 캐릭터 인기도 분석 1건(호요버스·블루 아카이브)이
별도 리포트로 붙습니다.

설문이나 비공개 데이터 없이 **이미 공개된 지표만** 쓰고, 12개 프로젝트가 모두
`수집 → 정제 → SQL → 시각화 → 대시보드` 의 같은 파이프라인을 따릅니다. 수집은 GitHub Actions 가
10분·매일·매주·매월 주기로 자동으로 돌립니다.

## 무엇을 발견했는가

- **팔로워 규모와 팬덤 밀도는 따로 움직인다.** 구독자 상위 멤버와 영상당 참여율 상위 멤버가
  거의 겹치지 않는다.
- **플랫폼마다 성장 곡선이 다르다.** 유튜브 구독자가 느리게 느는 멤버가 치지직 팔로워는 가장
  빠르게 늘기도 한다. 한 플랫폼 지표만 보면 성장을 오판한다.
- **경쟁사 비교는 데뷔 시기를 맞춰야 성립한다.** 구독자는 누적 지표라 2019년 데뷔 채널과
  2024년 데뷔 채널을 한 표에 올리면 실력이 아니라 활동 기간을 재게 된다. 그래서 스텔라이브
  각 기수를 같은 시기에 데뷔한 홀로라이브 기수와 짝지어 본다.
- **지표를 움직이는 건 평소 요인이 아니라 이벤트다.** 카테고리·시간대·요일을 바꿔서 얻는 배수는
  한 자릿수 초반인데 신의상 공개·데뷔 방송은 동시시청자를 자릿수가 다르게 끌어올린다.
- **팬은 돈을 쓰지만 회사에 남지는 않는다.** 정기 구독은 만원 미만, 한정 굿즈 펀딩은 1인당
  수십만원으로 지출의 자릿수가 바뀌는데, 동종업계 IP 회사의 감사 재무는 연속 영업적자다
  (스텔라이브 운영법인은 DART 에 없어 같은 방식으로 검증할 수 없다).

멤버별 수치는 표·차트에 그대로 두고, 결론 문장에는 멤버 이름을 붙인 순위를 쓰지 않습니다.
숫자는 실행할 때마다 데이터에서 다시 계산되므로 최신 값은 각 `REPORT.md` 와 PDF 에 있습니다.

## 작업 중 만난 데이터 함정

- **치지직은 방송이 꺼져 있어도 직전 방송의 동시시청자 수를 돌려준다.** 첫 수집에서 11채널 전부
  오프라인인데 1,600~3,800명으로 찍혔다. 상태를 확인해 0으로 정규화했다.
- **치지직 다시보기의 게시 시각은 방송 종료 시각이다.** 시작 시각으로 쓰면 "새벽 시작이 기본"으로
  읽힌다. 시작 = 게시 − 길이로 바로잡았다.
- **커버곡 수집이 재현되지 않았다.** 검색 상위 40개 창만 보고 있어 실행 시점마다 결과가 달랐다.
  업로드 재생목록 전량 열거로 바꾸니 결정적이 되고 쿼터도 3,300 → 173 units 로 줄었다.
- **경쟁사 표본을 인지도로 골랐다.** 유명한 순으로 뽑은 6명이 전원 2019~2020년 데뷔라 "구독자 10배
  차이"는 대부분 시작 시점 차이였다. 기수 전원으로 바꾸고 비교를 코호트 안으로 제한했다.
- **커버리지를 달력 시간으로 재고 있었다.** PC 를 하루 꺼두면 기간은 24시간이 넘지만 데이터는
  몇 시간치뿐이다. 실제 수집 간격으로 재도록 고쳤다.

전체 목록은 [방법론 페이지](app/src/app/methodology/page.tsx)에 무엇이 있었나 / 어떻게 발견했나 /
어떻게 처리했나로 적혀 있습니다.

## 데이터 원칙

- 비교는 비교 가능한 것끼리만 — 같은 표본, 같은 기간, 같은 시기에 시작한 사람들끼리.
- 수집 방식이 바뀌면 `_meta.json` 에 `method_changed_at` 을 남기고 그 경계를 넘는 비교는 하지 않는다.
- 데이터가 부족하면 결론을 내지 않고 "측정 불가"로 남긴다. 추정치로 채우지 않는다.
- `robots.txt` 가 막는 경로는 우회하지 않는다. 표본이 편향된 소스는 쓰지 않는다.
- API 키는 환경변수로만 쓴다.

## 저장소 구조

```
결과물/                프로젝트별 리포트·차트·대시보드, 리포트/ 에 PDF 4종
youtube_analyze_all/   분석 파이프라인 12개 (Python · pandas · SQLite · matplotlib)
app/                   통합 대시보드 (Next.js · TypeScript · 정적 export)
.github/workflows/     자동 수집 (live 10분 / daily / weekly / monthly)
PRD.md                 요구사항 정의서
HANDOVER.md            운영 인수인계서 (수집 상태·쿼터·다음 할 일)
```

## 실행

```bash
pip install -r youtube_analyze_all/requirements.txt       # 키 발급: youtube_analyze_all/SETUP_KEYS.md
python youtube_analyze_all/scripts/refresh.py --group daily   # 수집 → 분석 → 결과물/
python youtube_analyze_all/scripts/build_unified.py           # 종합 리포트 HTML (PDF 는 결과물/리포트/README.md)
cd app && npm install && npm run build                        # 대시보드 → app/out/ (HTTP 로 서빙)
```

디자인 토큰은 [Montage](https://github.com/wanteddev/montage-web)(Wanted Lab, MIT)의 값을,
PDF 서체는 Noto Sans KR(OFL)을 사용했습니다.
