# 버추얼 크리에이터 팬덤 애널리틱스

버추얼 크리에이터 그룹 **스텔라이브**를 중심으로, 공개 데이터만으로 팬덤 지표와 실제
재무 성과를 연결해 본 데이터 분석 포트폴리오입니다. 여기에 게임 캐릭터 인기도 분석
1건(호요버스)이 별도 리포트로 붙습니다.

설문이나 비공개 데이터 없이 **이미 공개된 지표만** 사용하며, 12개 프로젝트 모두
`수집 → 정제 → SQL → 시각화 → 대시보드`의 같은 파이프라인을 따릅니다.

```
결과물/                결과만 모아둔 폴더 — 프로젝트 12개 · 차트 70종 · 대시보드 12건
youtube_analyze_all/   분석 파이프라인 12개 (Python · pandas · SQLite · matplotlib)
app/                   통합 대시보드 (Next.js · TypeScript · 정적 export)
.github/workflows/     자동 수집 (live 10분 / daily / weekly / monthly)
PRD.md                 요구사항 정의서
```

코드는 건너뛰고 결과만 보시려면 **[`결과물/`](결과물/)** 부터 보세요.
한 파일짜리 종합본은 `python youtube_analyze_all/scripts/build_unified.py` 로
**스텔라이브 리포트**와 **게임 리포트** 두 권이 나옵니다.

## 무엇을 발견했는가

- **팔로워 규모 1위와 팬덤 밀도 1위는 다른 사람이다.** 구독자 상위 멤버와 영상당
  참여율 상위 멤버가 겹치지 않는다.
- **플랫폼마다 성장 곡선이 다르다.** 유튜브 구독자 증가 최하위권인 멤버가 치지직
  팔로워 증가에서는 1위였다.
- **경쟁사 비교는 데뷔 시기를 맞춰야 성립한다.** 구독자는 누적 지표라, 2019년 데뷔
  채널과 2024년 데뷔 채널을 한 표에 올리면 그 표는 실력이 아니라 활동 기간을 잰다.
  그래서 스텔라이브 각 기수를 **같은 시기에 데뷔한 홀로라이브 기수**와 짝지어 본다.
- **팬은 돈을 쓰지만 회사에 남지는 않는다.** 팬딩 월 구독 중앙값은 7,200원인데
  크라우드펀딩 1인당 후원액은 24.8만원(약 34배)이다. 그런데 이세계아이돌 소속사인
  패러블엔터테인먼트의 감사받은 FY2025 영업이익은 −91억원이고, 샌드박스네트워크는
  2018년 이후 8년 내내 영업적자다. (스텔라이브 운영법인은 DART 기업코드 마스터에
  없어 같은 방식으로 검증할 수 없다 — 비교 대상은 동종업계다.)

## 이 저장소에서 봐야 할 것

분석 결과보다 **[방법론 페이지](app/src/app/methodology/page.tsx)** 를 먼저 보시길
권합니다. 작업 중 실제로 발견한 데이터 함정을 무엇이 있었나 / 어떻게 발견했나 /
어떻게 처리했나로 기록했습니다. 몇 가지 예:

- **치지직은 방송이 꺼져 있어도 직전 방송의 동시시청자 수를 돌려준다.** 첫 수집에서
  11채널 전부 오프라인인데 1,600~3,800명으로 찍혔다. 그대로 쌓았다면 오프라인 구간이
  "시청자가 계속 있는 평지"로 그려졌을 것이다.
- **커버곡 수집이 재현되지 않았다.** `search.list` 상위 40개 창만 보고 있어서 같은
  코드·같은 채널인데 실행 시점에 따라 결과가 달라졌다. 업로드 재생목록 전량 열거로
  교체하니 결정적이 되었고 쿼터도 3,300 → 173 units로 줄었다.
- **경쟁사 표본을 인지도로 골랐다.** 홀로라이브 쪽 6명을 유명한 순으로 뽑으니 전원이
  2019~2020년 데뷔였고, 2023~2025년 데뷔인 스텔라이브와의 "구독자 10배 차이"는
  대부분 시작 시점의 차이였다. 표본을 **기수 전원**으로 바꾸고 비교를 코호트 안으로
  제한했다.
- **커버리지를 달력 시간으로 재고 있었다.** PC를 하루 꺼두면 `span`은 24시간을 넘지만
  실제 데이터는 몇 시간치뿐이다. "얇은 데이터로 만든 그럴듯한 차트"를 막으려던 가드가
  정확히 그 상황에서 무력해지는 구조였다.

## 실행

```bash
pip install -r youtube_analyze_all/requirements.txt
cd app && npm install
```

API 키는 환경변수로만 씁니다 (발급 절차는
[`SETUP_KEYS.md`](youtube_analyze_all/SETUP_KEYS.md)).

```bash
python youtube_analyze_all/scripts/refresh.py --group daily   # 수집 → 분석 → 사이트
python youtube_analyze_all/scripts/build_unified.py           # 종합 리포트 2권
cd app && npm run build                                       # 정적 대시보드 빌드
```

⚠ 빌드 결과물은 에셋을 `/_next/...` 절대경로로 참조합니다. **`file://` 로 열면 아무것도
로드되지 않으니** HTTP 로 서빙해야 합니다.

## 데이터에 대한 태도

- 수집 방식이 바뀌면 `_meta.json`에 `method_changed_at`을 남기고, 그 경계를 넘는 비교는
  하지 않습니다.
- 비교는 비교 가능한 것끼리만 합니다 (데뷔 코호트 매칭 — 같은 시기에 시작한 사람들끼리).
- 표본이 편향된 소스는 채택하지 않습니다 (Enka.Network — 쇼케이스 공개 유저만 잡히고
  공식 문서가 UID 열거를 금지).
- `robots.txt`가 막는 경로는 우회하지 않습니다 (텀블벅 — 수집 불가를 기록하고 출처를
  명시한 정적 데이터로 대체).
- 데이터가 부족하면 결론을 내지 않습니다 (FR-5 커버리지 가드).

디자인 토큰은 [Montage](https://github.com/wanteddev/montage-web) (Wanted Lab, MIT)의
값을 사용했습니다. 패키지가 GitHub Packages 전용이라 토큰 값만 이식했습니다.

### YouTube 쿼터

**자체 예산 8,000 units · 검색 90회**를 넘길 호출은 보내지 않는다. 실사용은 이 장부를 보면 된다.

### 결과물 · 리포트

- `결과물/` 은 daily·weekly 가 끝날 때마다 자동으로 다시 만든다.
- 리포트 PDF 4종(`결과물/리포트/`)은 **수동**이다. 현재 파일은 **2026-09-20 기준**이라 그 뒤 수집분
  (10 의 9/26 갱신 등)이 반영돼 있지 않다. 다시 만드는 법은 `결과물/리포트/README.md`.
- 스텔라이브 리포트와 게임 리포트는 **따로** 낸다. 요약판은 측정된 숫자만 싣되, 출처가 있는 공개 자료
  (07 시장 규모, 09 DART 재무)는 그대로 둔다.
- 커버곡 조회수는 **공식 MV + Topic 채널 음원 판을 곡 단위로 합산**한다(02·12).
- PDF 는 휴대폰에 맞춘 150×210mm. 바꿀 때마다 모바일에서 읽히는지 확인한다.

### 작업 규칙

- API 키는 환경변수로만(`YOUTUBE_API_KEY`, `DART_API_KEY`). 코드·커밋에 넣지 않는다.
- `robots.txt`·Cloudflare 로 막힌 곳은 우회하지 않고, 막혔다고 기록한다.
- 비교는 같은 표본·같은 기간끼리만. 수집 방식이 바뀌면 `_meta.json` 에 `method_changed_at`.
- `_meta.json` 의 한 dict 안에 성격이 다른 값(게임별 dict 와 합계 정수 등)을 섞지 않는다 — #65 의 원인.
- 작업은 `main` 에 바로 올린다. 마무리는 `CLAUDE.md` 의 "최적화" 7개 기준으로 확인하고 보고한다.

### 알려진 문제 · 남은 일

- 02 코드 주석에는 "유즈하 리코 - Topic" 채널이 있다고 돼 있으나 검색 결과는 계속 없음. 실제 채널이
  확인되면 `02_cover_song_ranking/collect.py` 의 `TOPIC_SEED` 에 넣는다.
- 저장소 전체(12개 프로젝트 + `app/`)에 대한 "최적화" 7개 기준 점검은 아직 안 했다. 최근 변경분만 했다.
- 리포트 PDF 가 9/20 기준으로 멈춰 있다(위 참고).
- Actions 로그에 Node.js 20 지원 종료 경고(`actions/checkout@v4`, `actions/setup-python@v5`). 지금은
  Node 24 로 강제 실행돼 동작에는 문제없다.
