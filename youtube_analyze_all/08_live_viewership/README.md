# 프로젝트 8 · StelLive 동시시청자 시계열 분석

치지직 멤버 채널의 **동시시청자를 10분 간격으로 직접 찍어 시계열을 만드는** 프로젝트입니다.

## 왜 별도 프로젝트인가

프로젝트3(치지직 방송 패턴)은 VOD 다시보기 목록으로 과거 방송 이력을 **소급 수집**할 수
있습니다. 하지만 동시시청자는 다릅니다:

- VOD는 `readCount`(누적 조회수)만 주고, 실시간 시청자 수를 남기지 않습니다.
- 치지직에는 동시시청자 히스토리 API가 없습니다.

즉 **지금부터 찍어 쌓는 것 말고는 만들 방법이 없는 유일한 데이터**입니다. 그래서 이 수집기는
파이프라인에서 가장 먼저, 그리고 계속 돌아야 합니다.

## 실행

```bash
python 08_live_viewership/collect.py --daemon --interval 10
```

상시 수집. 별도 터미널에서 계속 띄워두세요. 1회만 찍으려면 `--once`.

```bash
python 08_live_viewership/analyze.py
python 08_live_viewership/build_site.py
```

## 커버리지 가드

수집 시간이 곧 데이터인 프로젝트라, 스냅샷이 얇으면 차트가 우연에 좌우됩니다.
`analyze.py`는 **관측 24시간 + 라이브 세션 5건**에 도달하기 전까지 라이브 분석 결론을
내지 않고, 무엇이 더 필요한지만 알려줍니다.

팔로워 증감은 스냅샷 2개만 있어도 유효하므로 커버리지와 무관하게 먼저 산출합니다.

## 산출물

| 경로 | 내용 |
|---|---|
| `data/snapshots.csv` | 원본 스냅샷 (append-only, 계속 자람) |
| `data/member_metrics.csv` | 멤버별 집계 |
| `data/sessions.csv` | 재구성된 방송 세션 (라이브 관측 시) |
| `sql/viewership.db` | SQLite + 스키마·INSERT·분석쿼리·실행결과 |
| `charts/` | 팔로워 증감 · 동시시청자 시계열 · 피크 · 팬덤 밀도 |
| `site/index.html` | 대시보드 (외부 CDN 없이 SVG 직접 렌더) |

## 지표 정의

- **peak_ccu** — 관측 구간 내 최대 동시시청자. 10분 간격 샘플링이라 실제 순간 피크보다
  낮게 잡힐 수 있습니다(과소추정 방향이라 비교에는 안전).
- **세션** — 연속된 라이브 스냅샷을 하나로 묶은 것. 25분 이상 끊기면 다른 방송으로 봅니다.
  `observed_min`은 실제 방송 길이가 아니라 **관측된 길이**입니다.
- **ccu_per_1k_followers** — 팔로워 1,000명당 피크 동시시청자. 규모가 아니라 **팬덤 밀도**를
  봅니다. 프로젝트6의 "도달 효율" 지표와 같은 문제의식입니다.

## ⚠ 데이터 함정

치지직은 방송이 꺼져 있어도 `concurrentUserCount` / `accumulateCount` / `liveTitle`에
**직전 방송의 값**을 그대로 돌려줍니다. 실제로 첫 수집에서 11채널 전부 `status: CLOSE`인데
시청자 수가 1,600~3,800명으로 찍혔습니다.

그대로 쌓았다면 오프라인 구간이 "시청자가 계속 있는 평지"로 그려져 시계열 전체가
거짓이 됐을 것입니다. `common.chzzk.normalize_live_status()`에서:

- `is_live=False`면 라이브 지표는 `None`
- 잔존값은 `last_concurrent_users` / `last_live_title`로 분리 (참고용, **시계열 금지**)

## 수집 이력 메모

초기 프로토타입은 Node.js로 만들었고, 포트폴리오 언어 일관성을 위해 Python으로 이관했습니다.
이관 스크립트는 `migrate_from_node.py`이며 재실행해도 중복이 생기지 않습니다.
`stale-viewers` 버그 수정 이전에 수집된 20건은 스키마가 달라 이관에서 제외했습니다.
