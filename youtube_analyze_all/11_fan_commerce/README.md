# 11 · 팬 커머스

**질문** — 팬은 얼마를, 무엇에 쓰고, 그 돈은 회사에 남는가. 세 레이어로 나눠 본다 — 가격 구조(팬딩) · 실제 지출
(텀블벅) · 회사에 남는 것(DART, 09 재사용). 세 레이어는 확보 방법이 다르고 **그 차이 자체가 발견**이다.

- 갱신: weekly. API 키 불필요(공개 페이지 + 09 재사용)

## 실행

```bash
python collect.py      # 팬딩 REST 수집 + 텀블벅 정적 큐레이션 + 09 재사용 → data/
python analyze.py
python build_site.py
```

## 세 레이어

| 레이어 | 소스 | 확보 방식 | 뜻 |
|---|---|---|---|
| ① 가격 구조 | 팬딩 VTuber 카테고리 크리에이터의 공개 멤버십 페이지 | 자동 수집. `robots.txt` 는 관리·결제 영역만 막는다. Nuxt SSR 의 `__NUXT__` 에서 티어명·가격만 정규식으로 뽑는다 | 팬이 **요구받는** 금액. 구독자 수는 비공개라 매출은 추정하지 않는다 |
| ② 실제 지출 | 텀블벅 VTuber 관련 크라우드펀딩 | **자동 수집 불가** — 모금액이 `/api/` 에만 있고 `robots.txt` 가 `Disallow: /api/`. 헤드리스로 우회하지 않는다. 언론·플랫폼이 발표한 최종 수치와 1회 직접 열람한 수치를 출처와 함께 정적 큐레이션(`collect.py` 의 `CROWDFUNDING_PROJECTS`) | 재실행해도 갱신되지 않는다(`_meta.json` 의 `tumblbug_blocked_by_robots`) |
| ③ 회사에 남는 것 | `09_dart_financials/data/company_metrics.csv` | 읽기 전용 재사용. DART 를 다시 호출하지 않는다 | 팬딩은 DART 공시 0건이라 이 레이어에 없다 |

## 지표 정의

- 팬딩 가격 분포(최소·중앙값·평균·최대)는 유료 티어 전체 기준, 크리에이터별 평균가는 그 크리에이터 티어의 단순 평균.
- 달성률 = 모인 금액 ÷ 목표 × 100. **1인당 평균 후원액** = 모인 금액 ÷ 후원자 수 — 평균일 뿐 실제 결제 분포는 알 수 없다.
  팬메이드 광고 펀딩은 페이지가 목표금액을 안 보여줘 달성률로 역산했다(`goal_estimated`).
- 영업이익·영업이익률은 09 의 정의를 그대로 따른다.

## 읽는 법 · 한계

- 정기 구독은 만원 안팎, 자발적 팬 광고는 수만원, 한정 굿즈는 수십만원 — 지출은 "매달 얼마"가 아니라 **"이벤트에 얼마"**
  로 움직인다. 배수와 건수는 `REPORT.md`·12 에서 계산한다.
- **팬메이드 광고 펀딩은 회사 매출이 아니다.** 정산액이 광고비·외주비로 팬 커뮤니티 안에서 돈다고 창작자가 직접 공개한
  사례가 있다. 공식 굿즈 펀딩(이세계아이돌)과 규모를 직접 비교하면 안 된다 — 공식/비공식의 차이다.
- 크라우드펀딩 표본은 성공하고 화제가 된 프로젝트만 있다(생존 편향). 달성률 분포는 실제보다 낙관적이다.
- 세 레이어는 하나의 숫자로 합치지 않는다 — IP 소유자와 감사보고서 법인은 보도로만 연결되고, 회계연도와 캠페인 시점이
  다르며, 팬딩은 제3의 플랫폼이다. 상관계수를 내지 않는다.
