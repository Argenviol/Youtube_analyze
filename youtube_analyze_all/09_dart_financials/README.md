# 09 · DART 재무

**질문** — 팬덤의 돈은 어느 회사에 남는가. 포트폴리오에서 유일하게 인기 프록시가 아니라 **감사받은 법정 공시**를 다룬다.

- 데이터: Open DART API — 기업코드 검색 → 재무제표(XBRL 정기보고서 + 감사보고서 원문)
- 갱신: monthly(공시 주기가 분기·연간)

## 실행

```bash
export DART_API_KEY=...          # opendart.fss.or.kr 무료 발급. 없으면 즉시 중단
python collect.py --years 2016-2025
python analyze.py
python build_site.py
```

기업코드는 매 실행마다 DART 기업코드 마스터를 내려받아 **이름 완전 일치**로 찾는다(하드코딩·추측 없음).

## 두 개의 수집 경로

| 경로 | 대상 | 방법 |
|---|---|---|
| XBRL (`fnlttSinglAcntAll.json`) | 상장사·대형 비상장사의 정기보고서 | 구조화가 깔끔하지만 비상장 소규모 법인은 013(데이터 없음)이 정상 결과 |
| 감사보고서 원문 (`document.xml`) | 외부감사만 받는 비상장 법인 | `list.json`(`pblntf_ty=F`)으로 필링을 찾고 ZIP 안의 DART DTD XML 을 직접 파싱. XBRL 이 013 일 때만 자동 시도 |

원문 파싱은 각 재무제표 제목 뒤 **첫 번째** 표만 읽는다 — 본표는 "(단위: 원)", 주석 표는 "(단위: 천원)"이 많아
잘못 읽으면 1,000배 오차가 난다. 손실 전용 라벨("영업손실")은 항상 음수로 강제하고, 인접 연도의 전기 비교치로
자체 필링이 없는 연도를 메운다(자체 필링이 있으면 그쪽 우선). 파싱 검증은 `REPORT.md` 의 "감사보고서 원문 파싱" 절.

| 브레이브엔터테인먼트 | 동명이인 — K-pop 소속사로 VTuber Brave group 과 무관. 분석에서 제외 |

## 지표 정의

매출(영업수익)·영업이익·당기순이익·자산·부채·자본은 `account_id` 로컬명으로 매칭한다(계정명 표기가 연도·경로마다 다름).
영업이익률 = 영업이익 ÷ 매출, 자산회전율 = 매출 ÷ 자산총계, 자기자본비율 = 자본 ÷ 자산. 회사×연도 대표값은 연결 우선.
**인건비 비중은 산출하지 않는다** — 본표에 없고 주석 표는 단위·구조가 제각각이라 추정하지 않고 "산출 불가"로 둔다.

## 읽는 법 · 한계

- 플랫폼(NAVER·SOOP)은 관측 전 기간 흑자, IP 회사는 연속 적자 — 연도·수치는 `REPORT.md`.
- "팬덤 지표 ↔ 자사 재무"라는 원래 질문에는 답할 수 없다(스텔라이브 재무가 없다). 동종업계 **구조**에 대한 진술만 한다.
- 상관계수는 내지 않는다 — 표본 2~4개 회사, 회계연도와 팬덤 스냅샷의 기간 불일치.
- 치지직의 기여는 NAVER 재무에서 분리되지 않는다. 스트리밍 전업인 SOOP 이 더 나은 대리 지표다.
