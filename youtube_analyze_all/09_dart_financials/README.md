# 프로젝트 9 · DART 재무 분석

포트폴리오에서 유일하게 **조회수·구독자 같은 인기 프록시가 아니라 감사받은 법정 공시
데이터(재무제표)** 를 다루는 프로젝트입니다. Open DART(전자공시시스템) Open API로
스텔라이브·Brave group·팬딩(팬 커머스)·비교 크리에이터사의 기업코드를 검색하고,
확보 가능한 재무제표를 가져와 매출·영업이익·자산 효율을 분석합니다.

## 실행 방법

```bash
pip install -r ../requirements.txt
setx DART_API_KEY "발급받은_키"     # 새 터미널에서부터 적용됨. 절대 코드에 하드코딩하지 않는다.
python collect.py                   # 기업코드 검색 + 재무제표 수집(XBRL + 감사보고서 원문) -> data/
python analyze.py                   # 지표 산출 -> SQL/차트/리포트/사이트 데이터
python build_site.py                # site/index.html
```

키는 [OpenDART](https://opendart.fss.or.kr/)에서 무료로 발급받습니다. `collect.py`는
`os.environ["DART_API_KEY"]`로만 읽으며, 없으면 안내 메시지와 함께 즉시 중단합니다.

## 두 개의 수집 경로

09는 재무제표를 두 가지 경로로 수집합니다.

1. **XBRL 경로** (`fnlttSinglAcntAll.json`) — 상장사·대형 비상장사가 내는 **정기보고서**
   (사업·반기·분기보고서)에서 XBRL 태깅된 재무제표를 가져옵니다. 구조화가 가장 깔끔하지만
   대상이 좁습니다.
2. **감사보고서 원문 파싱 경로** (`document.xml`) — XBRL 경로가 013(데이터 없음)을 반환하는
   비상장 법인도 「외부감사법」에 따라 **감사보고서**는 매년 제출합니다. `list.json`
   (`pblntf_ty=F`)으로 그 필링을 찾고, `document.xml`이 주는 ZIP을 풀어 DART 자체 DTD
   (`dart3.xsd`/`dart4.xsd`) XML을 직접 파싱합니다. XBRL이 아니라 DART 전자공시 뷰어가
   렌더링하는 원본 서식이라 계정코드(별도재무제표) 또는 계정과목 텍스트(연결재무제표)로
   매칭해야 하지만, 재무상태표·손익계산서 본표는 표 구조가 안정적이어서 매출액·영업이익·
   당기순이익·자산총계를 신뢰성 있게 뽑아낼 수 있었습니다. 자세한 파싱 방법·단위 검증·
   교차검증은 `REPORT.md`의 "감사보고서 원문 파싱" 절을 참고하세요.

두 경로 모두 `collect.py` 안에 있고(XBRL 경로가 013을 반환할 때만 감사보고서 경로를
자동으로 시도), `analyze.py`가 두 경로의 결과를 같은 스키마(`account_id`의 로컬명 +
`sj_nm`)로 합쳐 이후 지표·차트·SQL·리포트를 만듭니다.

## 먼저 알아야 할 것: 이 프로젝트의 데이터는 여전히 얇습니다

09는 "스텔라이브 팬덤 지표를 실제 재무와 연결한다"는 목표로 설계됐습니다. 감사보고서 원문
파싱 경로를 추가한 뒤 **구조화된 재무제표를 확보한 곳은 NAVER·SOOP·샌드박스네트워크·
패러블엔터테인먼트 4곳**으로 늘었지만, 정작 **스텔라이브 본체, Brave group, 팬딩**은 여전히
확보하지 못했습니다 — 이유는 아래에 정직하게 남겨둡니다. 이건 버그가 아니라 이 프로젝트의
핵심 발견입니다.

## 왜 XBRL 경로만으로는 부족한가

`fnlttSinglAcntAll.json`(단일회사 전체 재무제표)은 XBRL이 태깅된 **정기보고서**
(사업보고서·반기보고서·분기보고서)만 파싱합니다. 이건 사실상 상장사와 일부 대형 비상장사의
몫입니다. 샌드박스네트워크·패러블엔터테인먼트·팬딩·브레이브엔터테인먼트 같은 비상장 법인은
「주식회사 등의 외부감사에 관한 법률」에 따라 **감사보고서**만 금융감독원에 제출하면 되고,
이 감사보고서 재무제표는 이 API가 파싱하는 XBRL 세트에 포함되지 않습니다 — 그래서
corp_code가 있어도 013(데이터 없음)이 정상 결과로 나옵니다.

다만 감사보고서 자체는 존재하고 DART가 그 원문을 공개하므로, `document.xml` 경로로 직접
파싱하면 013을 우회할 수 있었습니다(위 "두 개의 수집 경로" 참고). **XBRL 경로 하나만으로는
불충분하다는 결론은 여전히 유효합니다** — 두 번째 경로를 추가로 만들어야 했다는 사실 자체가
그 증거입니다.

팬딩은 두 경로 모두에서 0건입니다 — `data/filings.csv`에 팬딩 관련 행이 단 하나도 없습니다.
**프로젝트 11(팬 커머스)이 이 프로젝트의 DART 데이터로 팬딩의 매출·손익을 확인할 수는
없습니다.**

## 지표 정의

- **매출(영업수익)·영업이익·당기순이익·자산총계·부채총계·자본총계** — `account_id`의
  로컬명(예: `ifrs-full_Revenue`, `dart_OperatingIncomeLoss`, `dart-audit_Revenue`)으로
  매칭합니다. 계정명 표기가 연도·경로마다 다르기 때문입니다("영업이익" vs "영업이익(손실)"
  vs "영업손실"). 감사보고서 원문 파싱 경로는 손실 전용 라벨("영업손실" 등)의 값을 항상
  음수로 강제해서 부호를 통일합니다.
- **영업이익률** = 영업이익 / 매출, **자산회전율(자산 대비 매출 효율)** = 매출 / 자산총계,
  **자기자본비율** = 자본총계 / 자산총계.
- 연결(CFS)·별도(OFS) 모두 수집하되, 회사×연도 대표값은 **연결 우선**(없으면 별도).
  감사보고서 원문 파싱 경로는 인접 연도 필링의 전기(비교) 수치도 함께 뽑아, 해당 연도
  자체 필링이 없어도(예: 샌드박스네트워크 연결 2021·2023년) 비교치로 메꿉니다 — 자체
  필링이 있으면 항상 그쪽을 우선합니다.
- **인건비 비중은 산출하지 않았습니다.** 두 경로 모두 재무제표 본표(재무상태표·포괄손익계산서·
  현금흐름표·자본변동표)에는 인건비가 별도 계정으로 없습니다(기능별 표시 손익계산서라
  '영업비용' 한 줄). 인건비는 감사보고서 **주석**에만 나오는데, 주석 표는 단위가 '천원'으로
  바뀌는 경우가 많고 구조도 회사·연도마다 달라 이번 파싱 범위에서 의도적으로 제외했습니다 —
  추정치를 만들지 않고 '산출 불가'로 남겼습니다.
- **단위 검증.** 재무상태표·손익계산서 본표는 모두 "(단위 : 원)"이고, 주석 표는 종종
  "(단위: 천원)"입니다. 감사보고서 원문 파싱은 각 재무제표 제목 뒤 **첫 번째** 데이터
  표만 읽어 주석 표까지 잘못 읽는 1,000배 오차를 피합니다.

## 주요 결과 (수집 시점 스냅샷)

- 조사 대상 9곳 중 DART 기업코드 확인 6곳, **구조화된 재무제표 확보는 4곳**
  (NAVER·SOOP은 XBRL, 샌드박스네트워크·패러블엔터테인먼트는 감사보고서 원문 파싱).
- 2025년 매출: NAVER 약 12.0조원, SOOP 약 467억원, 샌드박스네트워크(연결) 약 731억원,
  패러블엔터테인먼트(별도) 약 218억원.
- 영업이익률: NAVER 18.3%, SOOP 26.8%로 흑자. 샌드박스네트워크는 2018~2025년 내내 영업손실,
  패러블엔터테인먼트는 2024년 흑자(5.8%)에서 2025년 대규모 적자(-41.7%)로 전환.
  샌드박스네트워크는 2024~2025년 연결기준 자본총계가 음수(완전자본잠식)로 전환됐다.
- 2016~2025 매출 CAGR: NAVER 12.9%/년 vs SOOP 21.7%/년.
- 스텔라이브·Brave group·팬딩 자체의 재무 데이터는 여전히 없어 "팬덤 지표 ↔ 자사 재무"라는
  원래 질문에는 이 데이터로 답할 수 없습니다. 패러블엔터테인먼트는 이세계아이돌 소속사이지만
  스텔라이브와는 다른 법인이라는 점도 유의해야 합니다.

## ⚠ 데이터 함정 및 한계

1. **013은 버그가 아니라 정상 결과 — 하지만 우회할 방법은 있다.** XBRL 경로는 비상장
   소규모 법인을 애초에 조회하지 못합니다. 그러나 감사보고서 원문(`document.xml`)을 직접
   파싱하면 대부분 우회할 수 있었습니다. 다만 팬딩처럼 **감사보고서 자체가 없는** 법인은
   이 경로로도 데이터가 나오지 않습니다.
2. **동명이인 주의.** DART에 "브레이브엔터테인먼트"라는 법인이 있고 재무 수치도 정상
   추출되지만, K-pop 걸그룹 '브레이브걸스' 소속사이며 스텔라이브를 인수한 일본의
   Brave group과는 무관합니다. 결과 통합·차트·리포트에서 계속 제외합니다.
